Contribuir

Agrega libros a la biblioteca con Git y GitHub

La biblioteca es un proyecto abierto: cualquier persona puede aportar libros. Todo el contenido vive en un repositorio de GitHub y se publica automáticamente con cada cambio aceptado.

Antes de comenzar, revisa las licencias aceptadas. Luego sigue la guía paso a paso para enviar tu primer libro usando el flujo profesional de contribución: Fork, rama de trabajo, Pull Request y revisión.

i

Importante: licencias aceptadas. Únicamente se aceptarán libros cuya licencia permita su distribución legal. Se recomienda contribuir únicamente con obras bajo licencias libres o abiertas, por ejemplo:

Creative Commons GPL LGPL FDL MIT BSD Apache 2.0 MPL Dominio Público

Existen muchas otras licencias compatibles. Antes de contribuir, verifica siempre que la licencia permita la redistribución legal del contenido.

  • No envíes libros protegidos por copyright sin autorización.
  • El colaborador es responsable de verificar la licencia antes de realizar la contribución.
  • Si existe alguna duda sobre la licencia, es preferible no enviar el material hasta confirmar que su distribución está permitida.
Guía de contribución

01Crea un Fork

Entra al repositorio oficial de la biblioteca y pulsa el botón Fork en la esquina superior derecha. Esto crea una copia del proyecto en tu cuenta de GitHub que podrás modificar libremente. Necesitas una cuenta de GitHub (es gratuita).

Durante la creación del Fork, asegúrate de copiar todas las ramas del repositorio y no únicamente la rama predeterminada. Si GitHub te muestra la opción que limita la copia a una sola rama, desmárcala.

El objetivo es que tu Fork también contenga la rama development, ya que será la rama que utilizarás durante toda la contribución.

02Clona el repositorio

Clona tu Fork en tu máquina local usando directamente la rama development y entra al directorio del proyecto. Reemplaza TU_USUARIO con el nombre de tu cuenta de GitHub. A partir de esa rama crearás tu propia rama de trabajo.

terminal

$ git clone -b development git@github.com:TU_USUARIO/biblioteca.git

$ cd biblioteca

# Si no tienes SSH configurado, usa HTTPS:

# git clone -b development https://github.com/TU_USUARIO/biblioteca.git

03Crea una rama de trabajo

Desde la rama development, crea tu propia rama de trabajo con un nombre corto y descriptivo, por ejemplo libros. Todas las modificaciones deben realizarse únicamente sobre esta rama y nunca directamente sobre development.

terminal

$ git checkout -b libros

# Crea y cambia a una rama nueva para tu contribución

04Agrega los archivos del libro

Copia los archivos del libro en los recursos del proyecto: el PDF en assets/pdf/ y la portada en assets/img/covers/.

estructura

assets/

├── img/covers/ ← copia aquí la portada (png, jpg o webp)

└── pdf/ ← copia aquí el libro (.pdf)

  • El nombre del PDF debe ser descriptivo, en minúsculas y con guiones, sin espacios ni acentos.
  • La portada se convierte automáticamente a webp al generar el sitio.

05Registrar el libro

El archivo que debes editar es assets/information/books.json. Ese archivo contiene el catálogo de libros de la biblioteca y es obligatorio registrar allí el nuevo libro para que el generador pueda incluirlo en el sitio.

Agrega un nuevo registro al final de la lista (recuerda la coma entre entradas), siguiendo exactamente el formato existente:

{

"title": "Título del Libro",

"file": "titulo-del-libro.pdf",

"cover": "titulo-del-libro.png",

"pages": 120,

"license": "CC-BY-SA",

"category": "GNU/Linux",

"tags": [

"linux",

"terminal"

],

"year": 2026

}

Cada campo tiene un significado:

  • title: título del libro tal como aparecerá en el sitio.
  • file: nombre exacto del PDF que colocaste en assets/pdf/.
  • cover: nombre de la portada en assets/img/covers/.
  • pages: número de páginas del libro.
  • license: licencia bajo la que se distribuye.
  • category: categoría del libro.
  • tags: etiquetas descriptivas para facilitar la búsqueda.
  • year: año de publicación.
  • Verifica que el PDF se abra correctamente antes de publicarlo.
  • Usa una categoría existente o agrega una coherente con el contenido.

06Genera el sitio

Ejecuta el generador para comprobar que todo funciona. La salida se escribe en la carpeta public/, que no debe editarse a mano.

terminal

$ ./generador.sh

# Genera la carpeta public/ con el sitio completo

i

Abre public/index.html en tu navegador para verificar que tu libro aparece con su portada, categoría y etiquetas correctas.

07Haz commit de los cambios

Registra los archivos agregados con un mensaje descriptivo que mencione el título del libro.

terminal

$ git add .

$ git commit -m "Agregar libro: Título del Libro"

08Envía tu contribución

Sube tu rama libros a tu Fork. El push envía los cambios exactamente a la rama libros que creaste antes, que será la base del Pull Request.

terminal

$ git push -u origin libros

En GitHub, abre tu repositorio y verás el botón Compare & pull request. Asegúrate de que el Pull Request se abra desde la rama libros de tu Fork hacia la rama development del repositorio oficial. Describe el libro que agregas y envía la solicitud. El equipo la revisará y, una vez aprobada, la biblioteca se actualizará automáticamente.

i

La rama development recibe actualizaciones una vez por semana, normalmente los domingos por la noche. Si tu Pull Request presenta conflictos, sincroniza primero tu Fork con la versión más reciente de development antes de continuar.

i

¡Gracias por contribuir al conocimiento libre! Si tienes dudas, revisa el repositorio oficial en GitHub.
